# 0.1.0

First release. The runtime configuration lives in `.env.js` and `appList.js`,
mounted next to `index.html` (`/usr/share/nginx/html` in the Docker image).
See `public/.env.example.js` and `public/appList.example.js`, and
[`docs/deployment.md`](../docs/deployment.md).

## Docker image

The image is built from the sources (`docker build -f apps/private/Dockerfile .`,
no `npm run build` beforehand) and differs from the `nginx:alpine` images of
the other Twake frontends:

- nginx listens on **port 8080**, not 80: update the published port, the
  target port of the reverse proxy (Traefik `loadbalancer.server.port`,
  Kubernetes `Service`) and the health checks;
- it runs as **user 101**, never root, and supports a **read-only root
  filesystem** when `/tmp` is writable (tmpfs, `emptyDir`);
- `GET /healthz` answers `200` for liveness and readiness probes (the image
  has a Docker `HEALTHCHECK` on it);
- the entrypoint of the nginx image runs (`/docker-entrypoint.d/`): do not
  override the command with a shell;
- it sends **security headers**, a `Content-Security-Policy` included. Allow
  the origins the app talks to with the environment variables below, or the
  browser blocks them.

## Container environment variables

| Variable | Default | Description |
|---|---|---|
| `CSP_CONNECT_SRC` | | Extra `connect-src` sources: the SSO origin with `AUTH_MODE = 'oidc'`; the JMAP origin and its `wss://` origin when JMAP is not on the origin of the app; the Sentry ingest origin |
| `CSP_FRAME_SRC` | | Extra `frame-src` sources: the Twake Drive application with `TDRIVE_ENABLED` (its stack goes to `CSP_CONNECT_SRC`) |
| `CSP_FRAME_ANCESTORS` | `'self'` | Origins allowed to embed the app in a frame (Twake Workplace) |
| `CSP_REPORT_URI` | | `report-uri` of the policy |
| `CSP_REPORT_ONLY` | `false` | `true`: report violations without blocking |
| `CONTENT_SECURITY_POLICY` | | Replaces the whole policy |
| `REFERRER_POLICY` | `same-origin` | |
| `PERMISSIONS_POLICY` | camera, microphone, geolocation... disabled | |

## App grid (in `appList.js`)

`var appList = [{ name, link, icon }]`, listed in this order. `link` and `icon`
may be URI templates (`{localpart}`, `{workplaceFqdn}`,
`{workplaceFqdn.localpart}`, `{workplaceFqdn.domain}`), resolved with the
`workplaceFqdn` claim of the SSO or else `WORKPLACE_FQDN_FALLBACK`: the Twake
Drive of each user has its own address, e.g.
`https://{workplaceFqdn.localpart}-drive.{workplaceFqdn.domain}`. An app whose
link cannot be resolved is left out.

## Twake Drive picker

With `TDRIVE_ENABLED`, the composer offers "Attach from Drive": the Drive
picker (a cozy-stack intent `PICK io.cozy.files`) opens in a dialog, and the
picked files are added as a link (a card in the message, the one tmail-flutter
writes) or as attachments (downloaded by the browser, then uploaded to JMAP).

- **OIDC only**: the ID token of the user is traded for a Drive token
  (`POST <TDRIVE_INTENT_URL>/auth/token_exchange`, `exchange_type: app`). The
  cozy-stack must allow it for the OIDC client of Twake Mail
  (`authentication.<context>.oidc.app_token_exchange.<client id>` with the
  `software_id` of a registered app, as `openpaas` → `registry://calendar` for
  Twake Calendar) and answer CORS for the origin of Twake Mail
  (`/auth/token_exchange`, `/intents`, `/files/downloads/`).
- **Content Security Policy** of the Docker image: the Drive app of the user
  in `CSP_FRAME_SRC` and its stack in `CSP_CONNECT_SRC` (`docs/deployment.md`,
  "Twake Drive picker").
- Messages of the picker are only accepted from the origin of the intent, from
  its frame, with its id, while the dialog is open; the answers go to that
  origin only, never `*`.

## AI assistant

The composer offers tmail-flutter's AI assistant when tmail-backend advertises
`com:linagora:params:jmap:aibot` with a `scribeEndpoint` (https). Nothing to set
in `.env.js`: the text the user asks about is sent to that endpoint only, with
the credentials of the JMAP session (OpenAI chat format, `{ messages }`). Add
its origin to `CSP_CONNECT_SRC` of the Docker image.

## SSO client

Register a public client (no secret) using Authorization Code with PKCE
(S256), with `<DOMAIN_REDIRECT_URL>/login-callback.html` (or
`SSO_REDIRECT_URI`) as redirect URI and
`<DOMAIN_REDIRECT_URL>/logout-callback.html` (or `SSO_POST_LOGOUT_REDIRECT`) as
post-logout redirect URI. Allow refresh tokens.

The keys shared with the `env.file` of tmail-flutter are listed, with those
this app ignores, in [`docs/deployment.md`](../docs/deployment.md#same-configuration-as-tmail-flutter).
